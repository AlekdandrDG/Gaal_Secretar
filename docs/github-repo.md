# GitHub: нужен ли он вам

**Короткий ответ: для простой установки — нет.**

Установщик Гэл берёт код из официального репозитория проекта автоматически. Вам не нужен аккаунт на GitHub, не нужно ничего скачивать и разбираться в незнакомых словах. При установке просто нажимайте Enter там, где спрашивают про GitHub, — и всё поставится само.

Эта инструкция — для тех, кто хочет большего. Прочитайте её, если планируете менять код Гэл или добавлять ей новые навыки.

**Сколько времени займёт:** 10 минут на регистрацию и форк.

---

## Что такое GitHub простыми словами

GitHub — это хранилище программного кода в интернете. Что-то вроде облачного диска, но со специальной способностью: он помнит **все версии** файлов. Любое изменение можно посмотреть, сравнить с прошлым и откатить назад.

**Репозиторий** — это папка проекта в таком хранилище. Код Гэл лежит в репозитории `AlekdandrDG/Gaal_Secretar`.

**Форк** — ваша личная копия чужого репозитория. Она полностью ваша: можете менять в ней что угодно, оригинал от этого не пострадает. При этом связь с оригиналом сохраняется — вы видите, что автор выпустил обновления, и можете забрать их себе.

---

## Зачем это может понадобиться

### 1. Свои правки не потеряются при обновлении

Гэл — живой проект, у неё выходят обновления. Если вы что-то поправили прямо на сервере, обновление может стереть ваши изменения. Если же правки лежат в вашем форке, они хранятся отдельно и никуда не денутся.

### 2. Новые навыки, написанные нейросетью

Гэл знает, как она устроена, и умеет дописывать себе новые возможности. Вы говорите ей: «хочу, чтобы каждое утро в 7:30 ты присылала прогноз погоды и советовала, что надеть» — она пишет себе код и начинает это делать.

Такой навык — это новые файлы на сервере. Если у вас есть форк, они сохраняются в вашем репозитории. Практический смысл:

- при переезде на другой сервер вы поставите Гэл со всеми накопленными навыками;
- если сервер сломается, ничего не пропадёт;
- если очередной навык что-то сломал, можно вернуться к рабочей версии.

### 3. История и возможность откатиться

Вы всегда видите, что и когда менялось. Сделали неудачное изменение — вернули как было. Это страховка, а не бюрократия.

### 4. Резервная копия

Особенно важно, если ваш хостинг не делает автоматических бэкапов (например, [JustHost](vps-justhost.md)). Ваш репозиторий на GitHub — это копия всего, что нажила Гэл, лежащая отдельно от сервера.

## Как сделать форк

### 1. Зарегистрируйтесь на GitHub

1. Откройте **github.com**.
2. Нажмите кнопку регистрации — обычно она называется **Sign up** и находится в правом верхнем углу.
3. Укажите почту, придумайте пароль и имя пользователя (латиницей — оно станет частью адреса ваших репозиториев).
4. Подтвердите почту по письму.

Бесплатного аккаунта достаточно, платить ни за что не нужно.

> Интерфейс GitHub на английском. Если это неудобно, включите в браузере автоматический перевод страницы — понимания хватит с запасом.

### 2. Откройте страницу проекта

Перейдите по адресу:

```
https://github.com/AlekdandrDG/Gaal_Secretar
```

Вы увидите список файлов проекта и его описание.

### 3. Нажмите Fork

Кнопка **Fork** находится в правой верхней части страницы, рядом с кнопками Star и Watch. На ней обычно нарисована вилка-развилка.

1. Нажмите **Fork**.
2. Откроется страница создания копии. Ничего менять не нужно — все поля уже заполнены правильно.
3. Нажмите кнопку подтверждения (**Create fork**).

Через несколько секунд у вас появится собственная копия проекта по адресу вида:

```
https://github.com/ВАШ_ЛОГИН/Gaal_Secretar
```

Готово. Форк сделан.

### 4. Скажите установщику, что ставить из вашей копии

При установке Гэл установщик спросит ваш логин на GitHub. Введите его — и код будет взят из вашего форка вместо официального репозитория.

Если на этом вопросе просто нажать Enter, установка пойдёт из официального репозитория. Это нормальный сценарий для тех, кто код менять не собирается.

Дальше установщик отдельно спросит, настраивать ли доступ на запись — то есть возможность Гэл самой сохранять изменения в ваш репозиторий. Для этого понадобится **Personal Access Token** — это как пароль, только для программ.

Где его взять: на GitHub откройте настройки своего профиля (Settings) → раздел для разработчиков (**Developer settings**) → **Personal access tokens**. Создайте новый токен с доступом к репозиториям и скопируйте его.

> ⚠️ Токен показывается **только один раз**, сразу после создания. Скопируйте его в менеджер паролей немедленно — увидеть его повторно нельзя, можно только создать новый.

Этот шаг тоже необязательный: без токена Гэл просто будет работать без сохранения изменений на GitHub.

## Если что-то пошло не так

**Не понимаю, нужен мне форк или нет.**
Если вы не планируете лезть в код и вас устраивает, что Гэл работает как есть, — не нужен. Форк можно сделать позже, когда появится необходимость: переустанавливать Гэл ради этого не придётся.

**Не могу найти кнопку Fork.**
Она в правом верхнем углу страницы репозитория, рядом со Star. Убедитесь, что вы вошли в аккаунт — неавторизованным пользователям кнопка неактивна. На узком экране телефона кнопки могут прятаться под значком «...».

**GitHub на английском, ничего не понятно.**
Включите перевод страницы в браузере: в Chrome и Safari он вызывается правой кнопкой мыши по странице.

**Потерял Personal Access Token.**
Восстановить нельзя. Удалите старый токен в настройках и создайте новый.

**Форк сделал уже после установки Гэл.**
Ничего страшного. Переключить бота на ваш репозиторий можно и потом — попросите об этом саму Гэл, она знает, как у неё всё устроено.
