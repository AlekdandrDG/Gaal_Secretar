# Google Календарь: доступ для Гэл

Эта настройка нужна, чтобы Гэл ставила встречи в ваш Google Календарь и сама вносила туда рейсы из присланных билетов. Займёт 20-30 минут — это самая длинная инструкция из всех, но делается один раз.

## Сначала главное: этот шаг можно пропустить

Календарь — **единственная необязательная часть**. Без него Гэл работает полностью: слушает голосовые, помнит, ищет по памяти, ставит задачи. Не будет только одного — событий в календаре и разбора билетов.

Установщик спросит: «Настроить Google Calendar сейчас?». Можно ответить «нет» и вернуться к этому позже в любой день.

Если решили делать — заложите полчаса спокойного времени. Google Cloud Console выглядит пугающе: это инструмент для программистов, там много разделов, которые вам не нужны. Идите строго по шагам и не сворачивайте в стороны.

---

## Что мы вообще делаем (в двух словах)

Обычно программа просит вас войти в Google и нажать «Разрешить». На сервере это неудобно: там нет браузера и некому нажимать. Поэтому делают иначе.

Мы заведём **служебный аккаунт** (по-английски *service account*) — это отдельный «робот-пользователь» Google со своим адресом электронной почты. У него есть свой пароль в виде файла, этот файл мы отдадим Гэл. А потом вы **поделитесь с этим роботом своим календарём** — ровно так же, как поделились бы с коллегой.

Отсюда три части работы:

1. Создать робота в Google Cloud Console и скачать его файл-пароль.
2. Открыть роботу доступ к своему календарю. **Этот шаг забывают чаще всего** — без него ничего работать не будет.
3. Вставить файл-пароль в установщик.

# Часть 1. Создаём робота в Google Cloud Console

## Шаг 1. Войдите в Google Cloud Console

1. Откройте браузер на своём компьютере.
2. Перейдите по адресу: **console.cloud.google.com**
3. Войдите под тем аккаунтом Google, **в календаре которого хотите видеть встречи**. Это важно: календарь и робот должны быть связаны с вашим рабочим аккаунтом.
4. При первом входе Google может показать условия использования — согласитесь. Может предложить бесплатный пробный период с привязкой карты — **это не нужно**, отказывайтесь или просто закройте предложение. Всё, что мы делаем, бесплатно.

Интерфейс на английском (язык можно переключить в настройках профиля, но названия ниже даны на английском — так надёжнее).

## Шаг 2. Создайте проект

Проект в Google Cloud — это просто папка для настроек. Одна штука, чтобы всё лежало вместе.

1. В самом верху страницы, слева, рядом с надписью «Google Cloud», есть выпадающий список — это выбор проекта. Если проектов ещё нет, там будет написано что-то вроде **Select a project**.
2. Нажмите на него. Откроется окно со списком проектов.
3. В этом окне справа сверху нажмите кнопку создания — называется примерно **New Project**.
4. В поле имени напишите: `Gael`
5. Поле про организацию (organization / location) оставьте как есть.
6. Нажмите кнопку создания (**Create**).

Проект создаётся несколько секунд. Затем **обязательно убедитесь, что вы в нём находитесь**: в верхнем выпадающем списке должно быть написано `Gael`. Если написано что-то другое — нажмите и выберите `Gael` из списка.

> Это частая ловушка: настройки делают в одном проекте, а робота ищут в другом. Проверяйте название вверху на каждом шаге.

## Шаг 3. Включите Google Calendar API

По умолчанию проект не умеет ничего. Нужно включить работу с календарём.

1. Слева вверху нажмите на значок из трёх горизонтальных полосок — это главное меню.
2. Найдите раздел, который называется примерно **APIs & Services** («сервисы»).
3. Внутри него выберите пункт про библиотеку сервисов — примерно **Library**.
4. Откроется страница с поиском. Введите в поиск: `Google Calendar API`
5. В результатах нажмите на карточку **Google Calendar API**.
6. На открывшейся странице нажмите большую кнопку **Enable** («включить»).

Кнопка подумает несколько секунд и превратится в надпись о том, что сервис включён (там же может появиться кнопка **Manage**). Значит, готово.

Если вместо **Enable** сразу написано, что API уже включён — отлично, ничего делать не надо.

## Шаг 4. Создайте служебный аккаунт (робота)

1. Снова откройте главное меню (три полоски слева вверху).
2. Зайдите в раздел **APIs & Services**, а в нём — в пункт про учётные данные, называется примерно **Credentials**.

   *Альтернативный путь:* в главном меню есть раздел **IAM & Admin**, внутри него — **Service Accounts**. Оба пути ведут к одному и тому же.
3. Сверху нажмите кнопку создания — примерно **Create Credentials**, и в выпавшем списке выберите **Service account**.
4. Заполните форму:

| Поле | Что вписать |
|---|---|
| Имя (service account name) | `gael` |
| Идентификатор (service account ID) | подставится сам — не трогайте |
| Описание (description) | можно оставить пустым |

5. Нажмите кнопку продолжения (**Create and continue**).
6. Дальше предложат выдать роли (roles) и доступ пользователям. **Обе эти части можно пропустить** — они здесь не нужны. Нажимайте продолжение и затем завершение (**Done**).

## Шаг 5. Запишите адрес робота

Вы вернётесь к списку служебных аккаунтов. В нём появилась строка с адресом вида:

```
gael@gael-123456.iam.gserviceaccount.com
```

**Скопируйте этот адрес и сохраните в заметки.** Он понадобится в части 2 — именно ему вы откроете доступ к календарю.

Выглядит он как обычная почта, только с длинным хвостом `.iam.gserviceaccount.com`. Письма туда писать бессмысленно — это адрес-идентификатор.

## Шаг 6. Создайте файл-пароль (JSON-ключ)

Теперь получим файл, который заменяет роботу пароль.

1. В списке нажмите на строку с вашим служебным аккаунтом — откроется его страница.
2. Сверху есть вкладки. Перейдите на вкладку про ключи — называется примерно **Keys**.
3. Нажмите кнопку добавления ключа — примерно **Add Key**, и в выпавшем меню выберите создание нового (**Create new key**).
4. Появится выбор формата: **JSON** и **P12**. Выберите **JSON** — он выбран по умолчанию.
5. Нажмите кнопку создания (**Create**).

Браузер сразу скачает файл на ваш компьютер. Имя будет длинное и непонятное, например `gael-123456-a1b2c3d4e5f6.json`. Ищите его в папке «Загрузки» (Downloads).

> ⚠️ **Этот файл — пароль от робота.** Скачивается он один раз: если потеряете, посмотреть заново нельзя, придётся создавать новый ключ (это не страшно и делается за минуту).
>
> Не отправляйте файл в чаты, не выкладывайте никуда и не показывайте его содержимое на скриншотах.

**JSON-файл** — это обычный текстовый файл, просто с фигурными скобками внутри. Открывается любым текстовым редактором: «Блокнот» на Windows, «TextEdit» на Mac. Не открывайте его двойным щелчком — система может попытаться запустить непонятную программу. Лучше: правая кнопка мыши → «Открыть с помощью» → текстовый редактор.

Внутри вы увидите что-то вроде:

```json
{
  "type": "service_account",
  "project_id": "gael-123456",
  "private_key_id": "a1b2c3...",
  "private_key": "-----BEGIN PRIVATE KEY-----\n...очень длинная строка...\n-----END PRIVATE KEY-----\n",
  "client_email": "gael@gael-123456.iam.gserviceaccount.com",
  ...
}
```

Две вещи, на которые стоит посмотреть:

- первая строка должна быть `"type": "service_account"` — установщик проверяет именно её;
- строка `client_email` — это тот самый адрес робота из шага 5. Если вы его не записали, возьмите отсюда.

# Часть 2. Открываем роботу доступ к календарю

**Это ключевой шаг. Именно его пропускают, а потом удивляются, что события не появляются.**

Робот создан, но он сам по себе — как новый сотрудник в первый день. Ваш календарь ему пока не виден. Нужно поделиться.

## Шаг 7. Откройте настройки своего календаря

1. Откройте в браузере Google Календарь (адрес — **calendar.google.com**).
2. Убедитесь, что вошли под тем же аккаунтом, под которым делали проект.
3. Слева есть список ваших календарей — раздел называется примерно «Мои календари» (**My calendars**). Обычно там первым идёт календарь с вашим именем — он основной.
4. Наведите мышь на нужный календарь. Справа от названия появятся три точки. Нажмите на них.
5. В выпавшем меню выберите пункт настроек — называется примерно «Настройки и общий доступ» (**Settings and sharing**).

## Шаг 8. Добавьте робота в доступ

1. Откроется страница настроек календаря. Прокрутите её вниз.
2. Найдите блок про доступ для отдельных людей — называется примерно «Предоставить доступ пользователям» или «Открыть доступ отдельным пользователям» (**Share with specific people**).
3. Нажмите кнопку добавления — примерно «Добавить пользователей» (**Add people**).
4. В поле адреса вставьте адрес робота, который вы сохранили в шаге 5:

   ```
   gael@gael-123456.iam.gserviceaccount.com
   ```

   Google может подчеркнуть его или предупредить, что такого контакта нет — это нормально, продолжайте.

5. Рядом будет выпадающий список с уровнем доступа. **Выберите «Внесение изменений в мероприятия»** (в английском интерфейсе — *Make changes to events*).

   Про уровни доступа:

   | Уровень | Подходит? |
   |---|---|
   | Просмотр информации о занятости | ❌ Гэл не увидит деталей |
   | Просмотр всех мероприятий | ❌ читать сможет, добавлять — нет |
   | **Внесение изменений в мероприятия** | ✅ **это нужный вариант** |
   | Внесение изменений и настройка доступа | не требуется, но тоже сработает |

6. Нажмите кнопку отправки (**Send** / «Отправить»).

Робот появится в списке людей с доступом. Письмо ему, разумеется, не придёт и подтверждать он ничего не будет — доступ работает сразу.

## Шаг 9. Проверьте, что доступ на месте

Прокрутите тот же блок ещё раз и убедитесь, что в списке есть строка с длинным адресом `...iam.gserviceaccount.com`, а рядом — «Внесение изменений в мероприятия». Если строки нет — повторите шаг 8, изменения могли не сохраниться.

# Часть 3. Отдаём файл установщику

Когда установщик дойдёт до вопроса «Настроить Google Calendar сейчас?», отвечайте `y` и нажимайте Enter.

Дальше он попросит **вставить содержимое JSON-файла**. Файл целиком загружать некуда — вы просто скопируете текст из него и вставите в окно терминала.

## Шаг 10. Скопируйте текст из файла

1. Найдите скачанный JSON-файл (папка «Загрузки»).
2. Откройте его текстовым редактором: правая кнопка мыши → «Открыть с помощью» → «Блокнот» (Windows) или «TextEdit» (Mac).
3. Выделите **весь** текст: `Ctrl+A` на Windows, `Cmd+A` на Mac.
4. Скопируйте: `Ctrl+C` на Windows, `Cmd+C` на Mac.

Важно скопировать всё — от первой фигурной скобки `{` до последней `}`.

## Шаг 11. Вставьте в терминал и завершите ввод

1. Переключитесь в окно терминала, где идёт установка.
2. Вставьте скопированное:
   - на Windows в большинстве терминалов — правая кнопка мыши или `Ctrl+Shift+V`;
   - на Mac — `Cmd+V`.
3. На экране появится текст ключа — это нормально.
4. Нажмите **Enter**.
5. Нажмите **Ctrl+D** — это сочетание означает «ввод закончен».

Терминал не задаёт вопросов «вы уверены?» — после Ctrl+D он сразу примет текст.

Если всё хорошо, установщик напишет, что данные Google сохранены. Если он ответит, что это не похоже на service account JSON, — текст скопировался не полностью. Повторите шаги 10-11, выделяя весь файл целиком.

> ⚠️ **Если у вас идёт запись экрана или трансляция — остановите её до вставки.** На экране появится приватный ключ робота, и кто его увидит, получит доступ к вашему календарю. Установщик предупредит об этом отдельно и сам очистит экран сразу после того, как сохранит ключ. Если ключ всё же попал в запись — удалите его в Google Cloud Console (ваш service account → «Ключи») и создайте новый.

## Подключить позже

Если вы пропустили этот шаг при установке, ничего страшного. Запустите установщик ещё раз той же командой из README: он не станет переделывать уже сделанное, дойдёт до вопроса про календарь и спросит снова.

Можно и вручную: положить тот же JSON-файл на сервер по пути `data/secrets/google-credentials.json` внутри папки с Гэл и перезапустить её командой `sudo systemctl restart d-brain-bot`.

Проще всего — попросить Гэл: напишите ей, что хотите подключить календарь, она подскажет, что сделать.

## Что должно быть на руках

- [ ] скачанный JSON-файл (лежит в «Загрузках», не удаляйте его);
- [ ] адрес робота вида `...@....iam.gserviceaccount.com`;
- [ ] в настройках Google Календаря этот адрес добавлен с правом «Внесение изменений в мероприятия».

## Если что-то пошло не так

**Не могу найти нужный пункт меню в Google Cloud Console.**
Интерфейс большой и периодически меняется. Самый надёжный способ — поиск: вверху страницы есть строка поиска по консоли. Введите туда `Service Accounts` или `Calendar API` и переходите по найденному. И проверяйте, что вверху выбран проект `Gael`.

**Установщик пишет: «Это не похоже на service account JSON».**
Скопировалась не вся строка текста или в буфере оказалось что-то другое. Откройте файл заново, выделите всё сочетанием `Ctrl+A` (`Cmd+A`), скопируйте и вставьте ещё раз. Проверьте, что текст начинается с `{` и содержит `"type": "service_account"`. Если файл потерялся — вернитесь к шагу 6 и создайте новый ключ, старый потом можно удалить.

**События не появляются в календаре, хотя всё установлено.**
В девяти случаях из десяти пропущена часть 2 — доступ к календарю. Откройте настройки своего календаря и проверьте, есть ли там адрес робота с правом «Внесение изменений в мероприятия». Вторая по частоте причина — доступ выдан с правом только на просмотр: тогда Гэл видит календарь, но не может ничего добавить. Третья — доступ открыт не тому аккаунту: сверьте адрес робота в настройках календаря со строкой `client_email` внутри JSON-файла, они должны совпадать символ в символ.

**Google просит привязать карту / предлагает пробный период.**
Отказывайтесь. Google Calendar API для личного использования бесплатен, платный тариф вам не нужен.

**Потерял JSON-файл.**
Не проблема. Зайдите в служебный аккаунт, вкладка ключей, создайте новый ключ — скачается новый файл. Старый ключ можно удалить там же. Робот и выданный ему доступ к календарю при этом остаются, заново делиться календарём не нужно.
